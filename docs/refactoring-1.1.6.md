# v1.1.6 渐进重构计划

基线：`1669a1d`。每轮只做一个模块，完成审查和验证后再进入下一轮。
目标是让职责与依赖清楚，保持当前 UI、交互、数据格式和设置兼容。
执行模型：GPT-6.1 Terra；主代理负责范围与结果审查。

## 顺序

1. **离线下载编排**（本轮）
   - 从约 1,487 行的 `ThreadRepository.kt` 抽出整串离线下载服务。
   - 保留公开仓库接口；分别明确网络获取、缓存写入、图片下载和手动模式副作用。
   - 给增量分页决策补特征测试，守住原末页刷新、缺页补齐和取消行为。
   - 保留后台更新单请求串行、限速和请求间隔。
2. **设置页**（约 2,064 行）
   - 按外观、阅读、编辑、网络与离线、备份等拆成分组组件，输入弹窗单独管理。
   - 保持设置键、默认值、备份字段、页面顺序和视觉样式。
3. **详情页界面**（约 2,078 行）
   - 抽出顶栏、楼层列表、操作弹窗和编辑入口，让页面只负责状态连接。
   - 保持列表 key、滚动状态与保存位置，避免状态随组件拆分被重建。
4. **详情 ViewModel**（约 1,483 行）
   - 分轮提取引用解析、回复草稿、分页阅读职责；每次只处理其中一项。
   - 分页/跳页/续读是高风险部分，先补边界验证再拆。
5. **图片查看器**（约 1,638 行）
   - 拆分页加载、手势状态、工具面板与保存分享操作。
   - 保持图片索引、缩放边界、预测性返回以及打开引用图片的行为。
6. **导航与富文本**
   - 分别整理页面层级转场与主 Tab 容器、富文本解析与绘制。
   - 保留页面常驻、触摸区域、动画参数和首帧预热；保护骰子与防剧透排版。

## 每轮验收

- 不为减少行数而搬运代码：新模块需要清楚的职责、输入输出与依赖方向。
- 不引入循环依赖，不升级 Compose / Material 3，不改既有存储格式。
- 检查实际 diff，运行 Kotlin 编译与相关单元测试；交互变更需要实机验证。
- 每轮一个独立提交，方便审查与回退；出现行为变化时单列说明。
- 构建日志、证书、密钥和本机配置不纳入提交。
